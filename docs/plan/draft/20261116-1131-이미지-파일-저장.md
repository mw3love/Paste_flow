# 이미지 원본을 DB 밖 파일로 옮겨 DB가 부풀지 않게 한다

상태: 초안
만든 날: 2026-11-16 11:31

## 지금 무엇이 불편한가

리모델링 진단(`docs/remodel/20261116-진단.md`)에서 사용자가 「바꾼다」로 판정한 칸(2026-11-16). 언어는 파이썬 유지 — 이 일은 파이썬 안에서 한다. 순서: 시험과 검사 → 이미지 파일 저장 → 폴더 구조(앞 일이 뒤 일의 안전망).

이미지 원본이 DB 안 BLOB으로 저장돼(`pasteflow/database.py:56`) 119MB DB에서 목록 조회가 140ms 걸렸고, mmap 512MB로 땜질했다(`pasteflow/database.py:25`부터). 시작 때 부풀면 압축(`_compact_if_bloated`)한다.

## 원하는 동작

- 이미지·큰 바이트는 `%LOCALAPPDATA%\PasteFlow\blobs\<해시>` 파일로, DB엔 경로·해시만. 같은 그림은 한 번만 저장.
- 기존 DB의 BLOB을 파일로 옮기는 1회 이전(PC 3~4대가 각자 돈다, 실패해도 데이터를 잃지 않게).
- 히스토리 한도 초과·삭제 때 파일도 같이 지우고, 어디에도 안 쓰이는 파일은 시작 때 청소.

## 어떻게 되면 끝인가

새로 복사한 이미지가 파일로 저장되고 DB 크기가 이미지 수와 무관하게 작게 유지된다. 기존 DB가 이전된 뒤에도 히스토리·고정 이미지가 그대로 보이고 붙는다. `tests/test_database.py`가 통과한다.

## 하지 않는 것

- 설정 저장 방식 바꾸기(두 설계가 갈렸고 지금 문제 없음 — DB 유지).
- 클립보드 형식별 「복원 가능/일부/세션만」 상태 기록(GPT 제안) — 따로.

## 정해 둔 것 · 모르는 것

- 정해 둔 것: 이미지만 파일로, 설정은 DB.
- 모르는 것: HTML·RTF·앱 전용 형식(노션)의 큰 바이트도 파일로 뺄지 · 이전이 중간에 끊겼을 때의 처리 · mmap·압축 땜질을 걷어낼지.
