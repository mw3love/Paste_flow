## 1. 지금 상태

- 이미지 원본은 `clipboard_items.image_data` BLOB 칸에 저장된다(표 정의 `pasteflow/database.py:56`, 저장 `pasteflow/database.py:114`의 `save_item`). 읽기는 `SELECT *` → `_row_to_item`(`pasteflow/database.py:437`, 457줄이 `image_data=row["image_data"]`). 목록용 요약 조회는 이미 `NULL AS image_data`로 원본을 빼고 읽는다(`pasteflow/database.py:176`·`:206`).
- 이 때문에 DB가 커졌다: 119MB DB에서 목록 조회가 140ms → mmap 512MB로 땜질(`pasteflow/database.py:25`부터 29까지 주석) · 항목 23개(실데이터 2MB)인 DB가 264MB(빈 페이지 99%) → 열 때 조건부 VACUUM(`pasteflow/database.py:34`부터 47까지).
- 지우는 자리: `delete_item`(`pasteflow/database.py:222`) · `clear_history`(`pasteflow/database.py:373`) · `_enforce_fifo_limit`(`pasteflow/database.py:380`, `save_item` 끝에서 부름) · `clear_memos`(`pasteflow/database.py:265` — 잠기지 않은 **고정 항목**을 모두 지운다. 고정 항목에는 이미지도 있다). 메모장 비우기 되돌리기는 지우기 전에 `get_pinned_items()`로 원본까지 읽어 둔 목록을 `restore_memos`(`pasteflow/database.py:277`)로 다시 저장한다(`pasteflow/main.py:2596`·`:2616`).
- 칸 추가 선례: `_create_tables` 안에서 `ALTER TABLE ... ADD COLUMN`을 시도하고 이미 있으면(`sqlite3.OperationalError`) 넘어간다(`pasteflow/database.py:69`부터 — `extra_formats`·`history_order`·`saved_image_path`·`is_locked`).
- 1회 이전 선례: `pasteflow/main.py:849` `_migrate_regen_thumbnails` — 요약 목록을 돌며 `get_item`으로 하나씩 읽고, 끝나면 `set_setting("thumbnail_regen_v2", "1")`. 시작 순서상 `pasteflow/main.py:3090`에서 부른다.
- DB 위치: LOCALAPPDATA 아래 PasteFlow 폴더의 pasteflow.db(`pasteflow/main.py:694`·`:703`). `Database`를 만드는 곳은 `pasteflow/main.py:1022` 한 군데.
- 시험: `tests/test_database.py`가 `Database(":memory:")`로 만든다(`tests/test_database.py:12`·`:233`). 파일 DB를 쓰는 시험도 있다(`tests/test_database.py:305`). 이미지 저장 시험 `tests/test_database.py:36`.
- 파일로 빼는 코드는 없다(「blob」「blobs」로 `pasteflow/`를 찾았으나 없음).

## 2. 원하는 동작

### 저장과 읽기 (사용자 눈에는 바뀌는 것 없음)

1. 이미지를 복사하면 `save_item`이 원본 바이트의 sha256 해시를 구해 `blobs\<해시>.bin`에 쓴다(이미 같은 파일이 있으면 다시 쓰지 않는다). 쓰기는 임시 파일에 쓴 뒤 이름 바꾸기로 한다(쓰다 끊겨도 반쪽 파일이 남지 않게).
2. DB 행에는 새 칸 `image_hash`에 해시를 넣고 `image_data`는 NULL로 둔다.
3. `get_item`·`get_recent_items`·`get_pinned_items`처럼 원본까지 읽는 조회는 `image_hash`가 있으면 파일을 읽어 `ClipboardItem.image_data`를 채운다. 파일이 없으면(지워졌거나 다른 PC에서 DB만 복사됨) `image_data`를 None으로 두고 한 줄 로그를 남긴다 — 앱이 죽지 않는다.
4. 요약 조회(`NULL AS image_data`)는 그대로 — 파일을 읽지 않는다.
5. 파일 읽고 쓰기는 새 파일 `pasteflow/blob_store.py`에 둔다(해시 · 쓰기 · 읽기 · 지우기 · 청소). `pasteflow/database.py`(491줄)를 더 키우지 않기 위해서다.
6. `blobs` 폴더 자리는 DB 파일과 같은 폴더. DB가 `":memory:"`(시험)면 임시 폴더를 만들어 쓴다.

### 지울 때

7. `delete_item`·`clear_history`·`_enforce_fifo_limit`·`clear_memos`가 행을 지운 뒤, 지운 행들이 쓰던 해시마다 남은 행이 그 해시를 쓰는지 세어 0이면 파일을 지운다.
8. 앱을 시작할 때(1회 이전 뒤) `blobs` 폴더의 파일 중 어떤 행의 `image_hash`도 아닌 것을 지운다. 임시 파일 찌꺼기도 지운다.

### 1회 이전 (기존 DB)

9. 시작할 때 설정 `images_to_files_v1`이 `"1"`이 아니고, `image_data`가 NULL이 아닌 행이 하나라도 있으면:
   - 먼저 DB 파일을 같은 폴더에 `pasteflow.db.bak-images-YYYYMMDD`로 복사한다(이미 있으면 다시 만들지 않는다). 복사가 실패하면 이전을 하지 않고 로그만 남긴다(이번 실행은 지금 방식으로 동작).
   - 그런 행을 하나씩: 파일 쓰기 → 그 행의 `image_hash` 채우고 `image_data` NULL로 → 커밋. 한 행이 실패하면 그 행은 그대로 두고 다음 행으로 간다.
   - 모든 행이 끝나면 `images_to_files_v1 = "1"`을 남기고 VACUUM 한 번.
10. 중간에 앱이 꺼지면 다음 실행에서 `image_data`가 남은 행부터 이어서 한다(파일을 먼저 쓰므로 데이터를 잃지 않는다).
11. 이 이전은 `Database`의 메서드로 두고, `pasteflow/main.py`의 다른 이전들 옆(`pasteflow/main.py:3090` 근처)에서 부른다.

## 5. 하지 않는 것

- 썸네일·HTML·RTF·앱 전용 형식을 파일로 빼기 — 사용자가 「이미지만」으로 정함.
- 설정 저장 방식 바꾸기 · 형식별 복원 상태 기록 — 리모델링 진단에서 뺌.
- mmap·자동 압축 걷어내기.
- 다른 PC 사이에서 `blobs` 폴더 동기화 — DB도 PC별이다(`pasteflow/main.py:694` 주석).
- 백업 파일 자동 삭제 — 사용자가 확인 뒤 지운다.
