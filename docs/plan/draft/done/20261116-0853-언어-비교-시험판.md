# 순차 붙여넣기만 C#·Rust+TypeScript(Tauri)로 작게 만들어 크기·메모리·시작 시간·타이밍을 실측하고 언어를 정한다

상태: 초안
만든 날: 2026-11-16 08:53

## 지금 무엇이 불편한가

리모델링 진단(`docs/remodel/20261116-진단.md`)에서 두 백지 설계가 모두 C# + WPF를 골랐다. 사용자는 Rust와도 비교하고 프로그램 용량도 보고 싶어 한다. 지금 exe는 103.6MB(실측)이고, C#·Rust 숫자는 자료에서 가져온 추정뿐이라 언어를 정할 근거가 부족하다. 다른 다섯 칸(화면 도구·폴더 구조·데이터 저장·시험과 검사·배포)도 언어가 정해질 때까지 「나중에」로 묶여 있다.

## 원하는 동작

- 순차 붙여넣기 핵심만 담은 작은 시험판을 C#(WPF)과 Rust+TypeScript(Tauri)로 하나씩 만든다: 클립보드 감시 → 줄에 쌓기 → Ctrl+Shift+V 키다운 때 그 키는 삼키고 클립보드를 다음 항목으로 바꾼 뒤 깨끗한 Ctrl+V를 주입(입력기 전환 팝업 방지 포함 — 지금 앱 `pasteflow/paste_interceptor.py:895`부터와 같은 방식) · 평범한 Ctrl+V는 통과시키고 줄만 비움 → 자체 쓰기 무시 · 트레이 아이콘 · 초점을 빼앗지 않는 작은 창 하나.
- 같은 조건으로 잰다: 실행 파일 크기(런타임 포함 / 미포함) · 쉴 때 메모리 · 시작해서 트레이에 뜨기까지 · 클립보드 교체 지연 · 여러 앱(메모장·워드·한글·브라우저·노션)에서 순서대로 붙는지.
- 지금 파이썬 앱도 같은 항목을 재서 세 줄짜리 비교 표를 만든다(2026-11-16에 메모리만 먼저 잼: 첫 실행 작업 집합 약 123MB).

## 어떻게 되면 끝인가

진단 문서에 세 언어의 실측 비교 표가 붙고, 사용자가 언어 칸을 판정한다(바꾼다 C# / 바꾼다 Rust / 유지). 그 뒤 나머지 다섯 칸을 다시 판정한다.

## 하지 않는 것

- 캡처·녹화·OCR·음성·주석 편집기 같은 나머지 기능은 시험판에 넣지 않는다.
- 시험판을 실제 앱으로 키우지 않는다.

## 정해 둔 것 · 모르는 것

- 정해 둔 것: 판정은 사용자가 한다. 비교 항목은 위 다섯 가지.
- 정해 둔 것(2026-11-16 추가): 메모리 예산은 120~150MB로 풀어도 된다 · Rust 쪽 화면은 TypeScript(Tauri) — 사용자가 TypeScript를 물어 2판 백지 설계까지 본 뒤 정함.
- 모르는 것: .NET SDK와 Rust 설치(합쳐 1GB 넘음)를 어느 PC에서 할지 · 진짜 키 입력으로 재는 시험은 사용자와 같은 데스크톱에서 돌아야 해서 언제 할지 · 지금 파이썬 앱의 메모리·시작 시간(전역 키 훅을 거는 앱이라 사용자 동의 뒤 잰다).
