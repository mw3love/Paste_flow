## 2. 원하는 동작

### 설치 (사람이 있어야 하는 단계)

1. `winget install --id Microsoft.DotNet.SDK.10` · `winget install --id Microsoft.VisualStudio.2022.BuildTools --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"` · `winget install --id Rustlang.Rustup` 뒤 `rustup default stable-msvc`.
2. 관리자 권한 창(UAC)이 뜨면 사용자가 눌러야 한다. `mw-build`로 무인 실행하다 UAC에서 막히면 묻지 말고 그 편을 「막힘: 설치에 관리자 승인 필요」로 남긴다.
3. 새로 깐 도구가 지금 셸의 경로에 안 잡히면 전체 경로로 부른다(`%USERPROFILE%\.cargo\bin\cargo.exe`, `C:\Program Files\dotnet\dotnet.exe`).

### 시험판 두 개 — 같은 기능

둘 다 다음만 한다(텍스트 클립보드만):

- 트레이 아이콘 하나. 시작해서 트레이 등록이 끝난 순간 `READY <유닉스 밀리초>`를 로그 파일 한 줄로 남긴다.
- 클립보드 변경 감시 → 텍스트면 줄에 쌓는다. 줄 규칙은 `pasteflow/paste_queue.py`와 같다(붙여넣기 시작 뒤 새 복사면 줄을 새로 · 10초 지나 새 복사면 새로 · 평범한 Ctrl+V면 비움). 자기 쓰기는 새 복사로 치지 않는다.
- 복사가 일어나면 화면 구석에 작은 창(줄 개수 표시)을 **초점을 빼앗지 않고** 띄운다.
- Ctrl+Shift+V: 그 키를 삼키고, 다음 항목을 클립보드에 쓰고, 깨끗한 Ctrl+V를 주입한다(지금 앱 방식 — 0칸). 훅이 키를 받은 시각과 클립보드 쓰기를 끝낸 시각을 `SWAP <받은 ms> <끝난 ms>`로 로그에 남긴다. 줄이 소진되면 개입하지 않는다.
- 로그 파일 자리: 시험판 exe 옆 `spike.log`.

C#: `spikes/csharp/` — .NET 10 WPF(`dotnet new wpf`로 시작), 키 훅·클립보드·키 주입은 Win32 직접 호출, 작은 창은 `WS_EX_NOACTIVATE`. 두 가지로 게시: 런타임 포함 단일 파일(`-r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true`)과 런타임 의존(`--self-contained false`).

Rust + TypeScript: `spikes/tauri/` — Tauri 2. `npm create tauri-app@latest`의 vanilla-ts 틀로 시작한다(네트워크 필요). 키 훅·클립보드·키 주입·트레이는 Rust(`windows` 크레이트), 작은 창의 화면은 TypeScript. 작은 창은 초점을 빼앗지 않게 띄운다(Tauri 창 설정 `focus: false`로 먼저 하고, 안 되면 Win32 `WS_EX_NOACTIVATE`를 Rust에서 덧붙인다 — 어느 쪽으로 됐는지 기록). 릴리스 빌드 exe 하나를 잰다.

### 자동 측정 — 스크립트 둘

`spikes/measure/measure.ps1 -Exe <경로> -Name <이름>`:
- 파일 크기(MB).
- 실행 → 30초 동안 1초 간격으로 그 프로세스와 **모든 자식 프로세스**(Tauri의 `msedgewebview2.exe` 포함, 부모 PID로 추적)의 작업 집합·개인 메모리 합계 → 30초 시점 값.
- 시작 시간: `spike.log`의 `READY` − 프로세스 시작 시각. `READY`가 없는 앱(지금 PasteFlow)은 메모리 합계가 3초 연속 1MB 안쪽으로 멈춘 첫 시각으로 대신한다(표에 「대리값」이라고 적음).
- 끝나면 프로세스 트리를 끈다(`taskkill /F /T`). 앱이 만든 데이터 폴더가 있으면 측정 전 상태로 되돌린다(지금 PasteFlow는 `%LOCALAPPDATA%\PasteFlow` — 측정 전에 없었으면 지운다).
- 결과 한 줄을 `spikes/measure/results.csv`에 덧붙인다.

`spikes/measure/paste_test.ps1 -Exe <경로> -Name <이름>`:
- (구현 때 바꿈) 대상 창은 메모장 대신 스크립트가 띄우는 시험용 글상자 창(WinForms, 글이 바뀌면 임시 파일로 내보냄)이다 — Windows 11 메모장은 저장 안 한 내용을 다음 실행 때 되살리고 사용자 메모장과 프로세스를 같이 쓸 수 있어, 아래 「메모장」은 이 시험 창으로 읽는다. 0칸·4칸은 그대로다.
- 시작 전 확인: 메모장이 이미 떠 있으면(사용자 것일 수 있다) 시험하지 않고 「중단 — 메모장이 이미 열려 있음」을 남긴다. 그래야 끝에 메모장을 꺼도 사용자 창을 건드리지 않는다.
- 시작 직전 사용자에게 한 줄 알린다(키 입력이 들어간다는 것). 시험 동안 맨 앞 창이 메모장도 시험판(그 프로세스 트리)도 아닌 창이 되면 **즉시 중단**하고 「중단 — 맨 앞 창이 바뀜」을 남긴다(이 PC는 감시 프로그램이 돈다). 시험판 자기 창이 맨 앞이 된 것은 「초점 빼앗음」으로 기록하고 메모장을 한 번 다시 맨 앞으로 되돌려 계속한다 — 두 번째로 빼앗기면 붙여넣기 단계는 건너뛰고 「순서: 못 잼(초점)」으로 남긴다.
- 시험판 실행 → 메모장 실행·맨 앞 → `Set-Clipboard`로 「하나」「둘」「셋」을 0.5초 간격 복사 → 매 복사 뒤 맨 앞 창이 여전히 메모장인지 기록(초점 빼앗김 여부) → Ctrl+Shift+V를 실제 키 입력(SendInput)으로 3번 → 메모장 글을 UI Automation으로 읽어 「하나둘셋」인지 본다(UI Automation으로 못 읽으면 메모장에 Ctrl+A·Ctrl+C를 넣고 `Get-Clipboard`로 읽는다 — 어느 쪽으로 읽었는지 기록) → `spike.log`의 `SWAP` 세 줄에서 지연(ms)의 최대값.
- 메모장은 시험이 띄운 그 프로세스만 저장하지 않고 끈다. 결과 한 줄을 `spikes/measure/results.csv`에 덧붙인다.

`results.csv` 열(첫 줄 머리): `when,kind,name,size_mb,ws_mb,private_mb,start_ms,start_is_proxy,swap_max_ms,order_ok,focus_kept,read_by,note` — `kind`는 measure 또는 paste. 해당 없는 칸은 비운다.

### 결과 정리

`docs/remodel/20261116-진단.md`의 「언어 — 백지 설계 2판」 절 아래에 「시험판 실측」 표를 붙인다. 열: 앱 · 파일 크기 MB · 30초 작업 집합 MB · 30초 개인 메모리 MB · 시작 ms(대리값 표시) · 교체 지연 최대 ms · 붙여넣기 순서 맞음 · 초점 안 빼앗음 · 만들며 막힌 곳. 행: 지금 PasteFlow · C# 단일 파일 · C# 런타임 의존 · Tauri.

실패했을 때: 시험판이 붙여넣기에 실패하면 두 번까지 고치고, 그래도 안 되면 그 실패 자체를 표의 「만들며 막힌 곳」에 적는다(비교 결과다). 빌드가 안 되면 오류 첫 줄을 적는다.

언어 판정은 이 문서가 하지 않는다 — 표가 나온 뒤 사용자가 진단 문서의 언어 칸을 판정한다.

## 5. 하지 않는 것

- 캡처·녹화·OCR·음성·주석 편집기·패널 목록 — 언어 판단에 핵심 위험(키 타이밍·초점·크기·메모리)만 보면 된다.
- 텍스트 말고 다른 클립보드 형식(이미지·HTML·노션) — 시험판 범위 밖. 형식 보존은 언어와 무관하게 Win32 호출로 같다(두 설계 모두 같은 방식 제안).
- 워드·한글·노션에서의 붙여넣기와 입력기 전환 팝업 확인 — 사용자가 「자동만」을 골랐다.
- 시험판을 실제 앱으로 키우기 · 지금 앱 코드 고치기.
- 언어 판정 — 사용자가 표를 보고 한다.
- 설치한 도구 지우기 — 판정 뒤 사용자가 정한다.
