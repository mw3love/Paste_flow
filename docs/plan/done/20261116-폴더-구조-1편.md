## 2. 원하는 동작

사용자 눈에는 아무것도 바뀌지 않는다 — 모든 단축키·드래그 붙여넣기·이미지 저장이 지금과 같이 동작한다.

### 도우미 함수 옮기기

1. 새 폴더 `pasteflow/winapi/`(빈 `__init__.py`)에 네 파일을 만들고, 1칸의 함수들을 **글자 그대로**(이름·본문·주석) 옮긴다: 드래그 붙여넣기 → `pasteflow/winapi/drag_paste.py` · 탐색기 → `pasteflow/winapi/explorer.py` · 바탕화면 → `pasteflow/winapi/desktop.py` · 이미지 → `pasteflow/winapi/image_io.py`.
2. 함수 이름은 바꾸지 않는다(앞의 밑줄 포함). 옮긴 함수가 쓰는 import·상수는 그 파일로 함께 옮긴다. 두 파일 이상에서 쓰는 상수는 처음 정의한 쪽 파일에 두고 다른 쪽이 가져온다. 옮긴 함수끼리 서로 부르면 그 모듈을 import한다. `pasteflow/winapi/` 파일은 `pasteflow.main`을 import하지 않는다(순환 import).
3. `pasteflow/main.py`는 옮긴 함수와 상수를 새 모듈에서 `from pasteflow.winapi.<모듈> import <이름들>`로 가져온다 — 클래스 안 코드는 한 글자도 바꾸지 않는다. 옮긴 뒤 `pasteflow/main.py`에서 더는 안 쓰는 import는 지운다.
4. 각 새 파일 머리에 한 줄 설명(무엇이 들어 있고 어디서 옮겨 왔나)을 둔다. 각 파일 300줄 아래.

### 키 판정 떼기

5. 새 폴더 `pasteflow/core/`(빈 `__init__.py`)에 `pasteflow/core/hotkey_rules.py`를 만든다. Windows·ctypes·Qt를 import하지 않는다.
6. 그 안에:
   - `Combo` — 단축키 하나(가상키 번호 + Ctrl/Shift/Alt가 필요한가). 가상키 0은 「설정 안 됨」.
   - `classify_keydown(vk, ctrl, shift, alt, win, injected, combos, capture_via_printscreen, stt_active, seq_paste_ready)` → `KeyDecision(plain_paste: bool, action: str 또는 None)`. `plain_paste`는 「평범한 Ctrl+V를 봤다」(관찰만 — 지금 코드도 관찰 뒤 아래 규칙을 계속 검사한다, `pasteflow/paste_interceptor.py:731`의 「fall through」). `seq_paste_ready`는 연타 방지를 통과했나(지금 코드는 0.1초 안의 반복이면 Ctrl+Shift+V 규칙을 건너뛰고 아래 규칙을 계속 검사한다, 711줄). 동작 이름: `"seq_paste"` · `"panel"` · `"ocr"` · `"seq_image_to_path"` · `"bulk_paste"` · `"bulk_path_paste"` · `"pin"` · `"memo"` · `"capture"` · `"capture_printscreen"` · `"record"` · `"stt_start"` · `"stt_repeat"`(이미 녹음 중인 반복 keydown — 삼키기만). `combos`는 이름 → `Combo` 사전.
   - 검사 순서와 조건은 1칸의 순서와 **똑같다**: 같은 키가 두 조건에 걸리면 지금 코드에서 먼저 검사하는 쪽이 이긴다. 수식키 비교는 지금처럼 Ctrl·Shift·Alt 각각 「필요 여부와 눌림이 같다」(`ctrl == combo.ctrl` 등 — 여분의 Ctrl·Shift·Alt가 눌려 있으면 안 맞음). Win은 PrintScreen 규칙에서만 본다(다른 규칙은 지금처럼 Win을 보지 않는다). Ctrl+Shift+V는 Alt가 안 눌렸을 때만. 평범한 Ctrl+V는 Ctrl만(Shift·Alt 없음)이고 주입 키면 `plain_paste`가 거짓.
7. `pasteflow/paste_interceptor.py`의 709줄부터 887줄까지의 조건문 사슬을 「`classify_keydown` 한 번 부르기 → `plain_paste`면 `on_plain_paste` 호출(콜백이 있을 때만, 지금처럼) → 동작 이름별로 지금과 같은 부작용 실행」으로 바꾼다. `seq_paste_ready`는 훅에서 지금처럼 `time.monotonic() - self._last_paste_time > 0.1`로 구하고, `seq_paste`를 실행할 때만 `_last_paste_time`을 갱신한다. 동작마다 지금 코드의 부작용을 그대로 옮긴다: Ctrl+Shift+V의 연타 방지(0.1초)와 `_on_ctrl_shift_v` 호출 뒤 삼키기 · 평범한 Ctrl+V는 `on_plain_paste` 호출 뒤 **통과**(삼키지 않음) · OCR·핀·메모·캡처·PrintScreen·녹화의 `AllowSetForegroundWindow` · 음성 입력의 Alt 조합 가상키 주입과 `_stt_active` 켜기 · 나머지는 콜백 뒤 삼키기. 동작이 `None`이면 지금처럼 `CallNextHookEx`로 통과.
8. `combos` 사전은 `set_*_hotkey`가 이미 풀어 둔 필드로 만든다(훅이 불릴 때마다 사전을 새로 만들지 말고, `set_*_hotkey`가 불릴 때 갱신해 둔다). Ctrl+Shift+V는 고정 조합이라 사전에 넣지 않고 함수 안에서 직접 본다.

### 시험

9. 새 파일 `tests/test_hotkey_rules.py`: 동작 이름마다 걸리는 경우와 안 걸리는 경우(수식키 하나 더·덜, 가상키 0, 주입 키), Ctrl+Shift+V가 다른 단축키보다 먼저인지, `seq_paste_ready`가 거짓이면 아래 규칙으로 넘어가는지, 평범한 Ctrl+V가 관찰되면서도 같은 키의 다른 규칙이 함께 걸리는지(지금 코드와 같게), 평범한 Ctrl+V가 주입 키면 관찰 안 됨인지, Win이 눌려 있어도 패널 등이 걸리는지, PrintScreen이 설정 꺼짐·수식키 있음이면 `None`인지, 음성 입력이 녹음 중이면 `"stt_repeat"`인지. 표 꼴(입력 → 기대 동작)로.
10. `requirements-dev.txt`에 `pyflakes`. 커밋 직전 검사 규칙은 바꾸지 않는다(pyflakes는 기존 코드에 경고가 많을 수 있어 이번 편의 확인 명령으로만 쓴다).

실패했을 때 보이는 것: 옮기다 이름을 빠뜨리면 `pyflakes`가 「undefined name」으로 잡는다. 키 판정 순서가 바뀌면 `tests/test_hotkey_rules.py`가 잡는다. 앱이 시작하다 죽으면 15초 실행에서 잡는다.
