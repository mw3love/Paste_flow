### 0편 — 성능 시험판(다른 편보다 먼저)

`spikes/live_draw/spike.py` 하나로 아래를 잰다. 앱 코드는 건드리지 않는다.

1. 커서 모니터를 덮는 테두리 없는 투명 창(`Frameless`·`Tool`·`WindowStaysOnTopHint`·`WA_TranslucentBackground`)을 띄운다. 배경은 알파 1(거의 투명)로 칠한다 — Windows는 알파 0 화소의 클릭을 아래 창으로 넘기므로, 그리기 상태에서 클릭을 받으려면 0이 아니어야 한다(추정 — 시험판이 확인한다).
2. `--auto`로 띄우면 시험판이 스스로 가짜 마우스 이벤트(`QApplication.sendEvent`로 누름·이동·뗌 — 운영체제 입력 주입 없음)를 보내 선을 긋고, 이동 하나마다 이벤트를 보낸 때부터 다시 그리기가 끝날 때까지의 시간을 `QElapsedTimer`로 재 `spikes/live_draw/result.txt`에 평균·95번째 값·최댓값을 적는다. 가로 모니터와 세로 모니터에서 각각 잰다. 선을 200개 넘게 그린 뒤에도 잰다(선이 쌓일 때 느려지는지).
3. `F8`(시험판 안에서만)로 클릭 통과를 켜고 끈다 — `SetWindowLongPtrW`로 `WS_EX_TRANSPARENT`만 바꾼다(창을 다시 만들지 않음). 통과 상태에서 아래 창 클릭이 되는지, 바꿀 때 깜빡이는지 본다.
4. `screen.grabWindow(0, …)`(녹화·영역 캡처와 같은 호출)로 그 모니터를 한 장 찍어 판서가 찍혔는지 `result.txt`에 적는다(찍힘 / 안 찍힘).
5. 결과와 판정을 `spikes/live_draw/README.md`에 적는다. 기준(4칸 첫 행)을 못 넘으면 0칸 「성능이 모자랄 때」대로 한다. 4번이 「안 찍힘」이면 Ctrl+C는 「화면 읽기 + 장면 그림 겹치기」로, 「찍힘」이면 툴바를 숨긴 채 화면 읽기만으로 만든다. 4번이 「안 찍힘」이면 녹화 중 판서는 이 문서에서 빼고 초안으로 적는다(0칸 「녹화 중 판서」).

### 1편부터 — 기능

**켜기.** 사용자가 `Ctrl+Shift+D`를 누른다.
- 그 순간 커서가 있는 모니터를 판서 창이 덮고 **그리기 상태**가 된다. 펜 도구가 골라진 채 시작하고, 툴바는 그 모니터 아래쪽 가운데에 뜬다(편집기 `_build_toolbar` 그대로 + 사라지는 펜). 툴바 왼쪽 끝 손잡이(`_DragBar`, `pasteflow/ui/image_annotator.py:2378`)를 왼쪽 버튼으로 끌면 툴바가 판서 창 안에서 움직인다. 툴바는 판서 창의 자식이라 `move()`로 옮겨도 된다 — 「프레임리스 창은 `startSystemMove`」 함정은 모니터를 넘나드는 최상위 창의 일이고, 판서 창 자체는 움직이지 않는다.
- 켜기 직전의 포그라운드 창 핸들을 기억한다(앱 쓰기로 돌아갈 때 돌려줌). 앱 쓰기에서 그리기로 돌아올 때도 그 순간의 포그라운드 창으로 새로 기억한다(앱 쓰기 동안 다른 앱으로 옮겼으면 그 앱으로 돌려주게 — 끝 검토 지적으로 고침).
- 판서 창은 포커스를 받는다(텍스트 도구가 키보드를 써야 하므로). 다른 앱이 포그라운드여도 맨 위에 오게 메모창의 `_force_foreground`(`pasteflow/ui/memo_window.py:76` — `AttachThreadInput` 뒤 `BringWindowToTop`)를 가져다 쓰고, 영역 캡처처럼 `SetWindowPos(HWND_TOPMOST)`를 한 번 더 건다.

**그리기 상태.** 이미지 미리보기 편집과 같은 조작이다.
- 도구 키 1부터 9까지와 0, Ctrl+Z 되돌리기, Del 지우기, 도구 우클릭 미니패널(색·두께) 모두 그대로. 도구별 색·두께는 미리보기 편집기와 같은 값을 공유한다(`_tool_defaults` — 클래스 값, DB `annot_tool_defaults`).
- 형광펜: 선택한 색의 반투명(알파 약 35%) 굵은 선(기본 두께는 펜의 3배쯤 — 구현 때 눈으로 맞춘다). 한 획 안에서 겹친 곳이 진해지지 않는다(한 경로로 그림).
- 사라지는 펜: 손을 뗀 뒤 1초 머물다 0.5초 동안 흐려지며 장면에서 빠진다. 되돌리기 목록에 안 들어간다. Ctrl+C 순간 화면에 남아 있는 것만 찍힌다.
- 손 도구(1, 선택): 그림을 고르고 옮긴다. 빈 곳을 끌어도 창은 안 움직인다(`_win_drag_*`는 아무것도 안 함). 휠 확대도 아무것도 안 함(`_on_wheel_zoom`).
- Ctrl+C: 판서 창의 툴바를 숨기고, 다시 그려질 틈을 주려고 `QTimer.singleShot(50, …)`(메인 스레드) 뒤에 그 모니터를 「화면 + 판서」 한 장으로 만들어 `_on_capture_region(pixmap, 모니터 사각형)`에 넘긴다 → 클립보드·히스토리·캡처 폴더 PNG·복사 토스트(영역 캡처와 똑같음). 판서는 그대로 계속된다. 그래서 판서 창에서는 Ctrl+C·Ctrl+V가 「주석 복제」가 아니다(호스트의 `copy_selection`이 화면 복사, `paste_selection`은 아무것도 안 함).
- Esc는 단계적으로 취소한다(뷰 `_AnnotatorView.keyPressEvent`, `pasteflow/ui/image_annotator.py:2300`이 이미 하는 순서): 텍스트를 쓰는 중이면 입력만 끝내고, 고른 그림이 있으면 선택만 풀고, 스포이드 중이면 스포이드만 끝낸다(호스트 `_on_escape` — 이미지 미리보기의 `pasteflow/ui/image_preview.py:403`과 같은 순서). 그 밖이면 그림을 모두 버리고 판서 창을 닫는다(칩이 떠 있으면 함께 닫고, 기억해 둔 창에 포그라운드를 돌려준다). 확인 창은 띄우지 않는다(관례 — ZoomIt도 Esc로 바로 끝).
- Space: 뷰가 호스트 `toggle_edit_mode`를 부르지만 판서 창에선 아무것도 안 한다(그리기와 앱 쓰기 전환은 단축키만).

**앱 쓰기 상태.** 그리기 상태에서 `Ctrl+Shift+D`를 다시 누르면:
- 그림은 그대로 보이고, 툴바는 숨고, 판서 창은 클릭 통과(`WS_EX_TRANSPARENT`)가 된다. 기억해 둔 창에 포그라운드를 돌려준다(그 창이 없어졌으면 그냥 둔다).
- 아래 앱을 평소처럼 쓴다. Esc는 판서가 받지 않는다(아래 앱으로 감).
- 판서가 켜져 있다는 표시로 모니터 오른쪽 위에 작은 칩 「판서 중 · Ctrl+Shift+D」를 띄운다(클릭 통과, `pasteflow/ui/toast.py`의 `ToastNotification` 지속형 칩 재사용 — `duration_ms=0`과 `anchor`에 모니터 오른쪽 위 점). 칩 모양은 구현 때 눈으로 맞춘다.
- 앱 쓰기로 넘어갈 때 텍스트를 쓰는 중이었으면 그 글을 확정한다(`clearFocus`). 이 상태의 Ctrl+C·Esc는 판서가 받지 않고 아래 앱으로 간다.
- 다시 `Ctrl+Shift+D`를 누르면 칩이 사라지고 클릭 통과가 꺼지고 툴바가 다시 보이며 판서 창이 포커스를 다시 잡아 그리기 상태로 돌아간다(같은 모니터 — 커서가 다른 모니터로 갔어도 판서는 처음 켠 모니터에 남는다).

**다른 기능과 만날 때.**
- 판서 중 Alt+F2 영역 캡처·녹화 단축키: 그 기능이 평소처럼 맨 위를 차지해 돈다. 판서 창은 닫지 않는다. 캡처에 판서가 찍히는지는 0편 4번 결과와 같다.
- 판서 중 패널(Ctrl+Space)·토스트: 판서 창보다 위에 떠도 된다(손대지 않음).
- 설정창에서 단축키를 녹화하는 동안은 훅이 멈추므로(`suspend()`) 판서 단축키도 안 먹는다 — 기존과 같음.

**실패할 때 보이는 것.**
- Ctrl+C 중 파일 저장이 실패하면 영역 캡처와 같은 토스트 「캡처 파일 저장 실패 — …」(`_on_capture_region`이 이미 함).
- 판서 창을 못 띄우면(커서 모니터를 못 찾음) 주 모니터에 띄운다.

### 흐름과 상태

| 여는 길 | 단계 수 | 상태별 처리 |
|---|---|---|
| `Ctrl+Shift+D`(설정에서 바꿀 수 있음, 설정창 「캡처·녹화」 페이지의 새 카드 「화면 판서」) | 켜기 1번 → 그리기 → (전환 1번) → 앱 쓰기 → (전환 1번) → 그리기 → Esc 1번 끝 | 그림 없음: 빈 투명 창 + 툴바. 앱 쓰기: 칩만. 키보드만: 도구 키·Ctrl+Z·Ctrl+C·Esc로 다 됨(펜 그리기 자체는 마우스·펜 필요). 되돌리기 어려운 것: Esc가 그림을 버림 — 관례대로 확인 없이, 남기려면 먼저 Ctrl+C |

### 사람 판단이 필요한 자리

- 0편 성능 판정: 기준을 못 넘고 Qt 안의 줄이기로도 안 되면 `mw-build`는 묻지 말고 그 편을 「막힘: 사용자 판정 필요」로 두고 멈춘다(뒤 편은 0편에 기대므로 다음 편으로 넘어가지 않는다).
- 형광펜 기본 두께·알파, 칩 모양: 눈으로 맞추는 값이라 구현자가 정하고 4칸 눈 행에서 사용자가 본다.

### 구현 중 정한 것

- 툴바 손잡이는 기존 `_DragBar` 대신 새 `_ToolbarGrip` — `_DragBar`는 전역 좌표를 부모 좌표로 그대로 써서 원점이 0이 아닌 보조 모니터에서 툴바가 어긋난다.
- 툴바의 저장 버튼도 Ctrl+C와 같은 화면 복사로 했다 — 캡처 폴더에 PNG가 남으니 따로 파일 저장 창을 띄우지 않는다.
- 툴바 자리는 모니터 아래 끝이 아니라 작업 표시줄 위(`availableGeometry` 아래 끝에서 28px) — 판서 창은 작업 표시줄까지 덮어서, 모니터 끝 기준이면 툴바가 작업 표시줄에 붙었다.
- 「판서 중」 칩 아이콘은 ✏, 글은 「판서 중 · Ctrl+Shift+D」(설정한 단축키를 따라감).
- 판서 창 안의 Ctrl+V는 아무것도 안 한다(미리보기 편집기의 「주석 붙여넣기」는 판서에 쓸모가 없다).

## 5. 하지 않는 것

- 여러 모니터 동시 판서 — 커서 모니터 하나만(0칸).
- 얼린 화면 판서 — 라이브로 정함(0칸).
- E 전부 지우기·Ctrl+S 파일 저장(ZoomIt 관례) — 요구 밖. 다 지우려면 Esc 뒤 다시 켜면 된다. 파일은 Ctrl+C가 캡처 폴더에 이미 남긴다.
- 화면 확대(ZoomIt 본기능)·지우개 도구 — 요구 밖.
- 판서를 껐다 켤 때 지난 그림 되살리기 — Esc는 버리기로 정함(0칸).
- Rust 등 다른 언어 — 0칸 「언어」. 0편이 끝내 기준을 못 넘으면 사용자가 다시 정한다.
- Windows Terminal 퀘이크 모드와의 충돌 처리 — 그 키(Win+백틱)를 안 쓰므로 해당 없음.
