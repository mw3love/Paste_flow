# 260713_구글드라이브 검색 연동 계획

AI 질의가 **내 구글 드라이브 문서를 근거로** 답하게 한다. 게이트웨이 Responses API가
중계하는 OpenAI 커넥터(`connector_googledrive`)를 검색 심부름꾼에 얹는 방식.

**현재 상태: 1단계 코드 작성 완료(미배선·미검증). 2·3단계 미착수.**
이어서 하려면 아래 「다음 세션에서 바로 할 것」부터 읽으면 된다.

---

## 실호출로 검증된 사실 (2026-07-13)

추측이 아니라 실제로 던져 보고 확인한 것들이다. 다시 검증할 필요 없다.

- **게이트웨이가 `mcp` 커넥터 도구를 중계한다.** Mindlogic 게이트웨이
  (`https://factchat-cloud.mindlogic.ai/v1/gateway`)의 Responses API에 아래 도구를 실어
  보내면 `mcp_list_tools`로 드라이브 도구 목록이 오고 `mcp_call`이 실제로 실행된다.

  ```python
  tools=[{
      "type": "mcp",
      "server_label": "gdrive",
      "connector_id": "connector_googledrive",
      "authorization": "<구글 OAuth 액세스 토큰>",
      "require_approval": "never",
  }]
  ```

- **진짜 토큰이면 실제 드라이브 파일명이 돌아온다** (OAuth Playground에서 받은
  `drive.readonly` 토큰으로 확인 — `recent_documents` 호출 → 실제 파일 3건 반환).
  가짜 토큰일 때는 같은 호출이 `http_error 500`으로 실패했다. 즉 **중계 + 인증 경로 모두 정상.**

- **커넥터는 읽기 전용**: `search` / `fetch` / `recent_documents` / `list_drives`.
  스코프는 `https://www.googleapis.com/auth/drive.readonly` 하나면 된다. 쓰기·수정은 불가.

- **액세스 토큰은 1시간 만료** → refresh token 흐름이 필수다(이게 이 기능의 실제 작업량 대부분).

- **공식(AI Studio) 백엔드는 이 기능을 못 쓴다.** `_ask_google_genai`는 `google_search`
  grounding만 붙고 커넥터 통로가 없다 → **게이트웨이 전용 기능**으로 간다.

---

## 설계 — 삽입점은 "도구 목록에 한 줄"

게이트웨이 AI 질의의 검색은 세 갈래인데, 셋 다 `tools=[...]`를 넘기는 지점이 있다.
거기에 `gdrive.drive_tool(token)`을 **하나 더 넣기만** 하면 된다.

| 경로 | 지금 | 드라이브 추가 지점 |
|---|---|---|
| GPT 모델 | Responses 내장 web_search | `ocr_engine._ask_openai_responses`의 `tools` |
| 그 외 모델 (claude·gemini…) | 도구 왕복 → `web_search.search()` → nano | `web_search._search_via_gpt`의 `tools` |
| 여러 모델 비교 | `web_search.prefetch()` → nano | `web_search.prefetch`의 `tools` |

**핵심:** 비GPT 모델은 자기가 검색하는 게 아니라 **nano 심부름꾼에게 시킨다.** 그래서 nano에
드라이브를 쥐여 주면 claude·gemini도 그대로 드라이브를 검색하게 된다 — 모델별 도구 호환성
지뢰(Llama-4-Maverick의 `tools` → 405, Gemini 3의 `thought_signature` 에코백 등)를 다시
밟지 않는 것이 이 방식의 진짜 이득이다.

**발동 정책(결정됨):** 질문창 체크박스 같은 옵트인 없이 **항상 도구로 제공하고 모델이 판단**한다
(웹 검색과 동일한 게이트키퍼 구조). 토큰이 없으면 도구만 조용히 빠진다(우아한 열화).

## ⛔ 다음 세션에서 바로 할 것 — Cloud Console 수작업 (사용자)

이게 안 되면 2·3단계가 전부 막힌다. Claude가 대신 못 하는 유일한 단계다.

1. https://console.cloud.google.com/ → 프로젝트 새로 만들기 (이름: `PasteFlow`)
2. **API 및 서비스 → 라이브러리** → `Google Drive API` → **사용 설정**
3. **OAuth 동의 화면** → 사용자 유형 **외부(External)** → 앱 이름 `PasteFlow`, 지원·개발자 이메일 본인
4. **데이터 액세스(스코프)** → `https://www.googleapis.com/auth/drive.readonly` 추가
5. ⚠ **대상(Audience) → `앱 게시`로 "프로덕션" 전환**
   — **테스트 상태로 두면 구글이 refresh token을 7일 만에 만료시킨다.** 프로덕션이면
   미검증 앱 경고가 최초 1회 뜨지만(`고급 → 계속`으로 넘김) 토큰이 오래 산다. 개인용이라 무해.
6. **사용자 인증 정보 → OAuth 클라이언트 ID → 애플리케이션 유형 「데스크톱 앱」** → 만들기
7. 나온 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 Claude에게 전달 → 1단계 실검증 재개
