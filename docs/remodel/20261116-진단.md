## 한눈에

두 백지 설계는 서로를 보지 않고도 같은 답을 냈다: **C# + WPF**, 순수 로직(Core)과 Windows 연결부를 나눈 구조, SQLite에 이미지는 파일로 따로, 300줄 파일 제한을 검사로, 단일 설치 파일 + 자동 업데이트(Velopack). 둘 다 2등 언어로 파이썬을 꼽지 않았다(Claude는 Rust, GPT는 C++/Qt).

지금 PasteFlow와 갈리는 곳은 여섯 칸 전부다. 다만 **언어·화면 도구는 통째로 다시 쓰는 일**(약 2만 줄)이고, **폴더 구조·데이터 저장·시험과 검사는 파이썬을 그대로 두고도 백지안의 핵심을 가져올 수 있다.**

## 언어 — 사용자 질문으로 더 본 것 (판정 전)

사용자가 「Rust와 비교」와 「프로그램 용량」을 물어 더 봤다.

| 만드는 방법 | 실행 파일 크기 | 근거 |
|---|---|---|
| 지금(파이썬 + PyQt6, 단일 exe) | 103.6MB | 실측(이 PC에서 `PasteFlow.spec` 빌드) |
| C# + WPF, 런타임 포함 단일 exe | 수십 MB(추정) | Microsoft 문서는 「런타임·프레임워크를 담아 크다」고만 함 · 미실측 |
| C# + WPF, PC에 .NET 런타임을 한 번 설치 | 수 MB(추정) | 미실측 |
| Rust + Tauri | 약 5MB | 블로그 측정(2023, 운영체제 미상) |
| Rust + egui | 약 18MB | 같은 블로그 |

- Rust 쪽 장점: 가장 작고 가벼움, 런타임 설치 없음, Microsoft 공식 `windows` 크레이트, 형의 AX Workhub(Rust + Tauri)를 참고 코드로 쓸 수 있음.
- Rust 쪽 약점: 이 앱의 핵심 화면(초점을 빼앗지 않는 창·화면 위 오버레이·주석 편집기)에서 Tauri는 초점 제어가 까다롭다고 두 백지 설계가 모두 지적. Rust 자체 화면 도구(egui·Slint)는 부품이 적음. 엄격한 컴파일러로 AI 수정 반복이 늘 수 있음.
- 이 PC에는 .NET SDK도 Rust도 없다(2026-11-16 확인) — 실측하려면 설치가 필요하다.
- **판정: 순차 붙여넣기 하나만 C#·Rust로 작게 만들어 크기·메모리·시작 시간·타이밍을 실측한 뒤 정한다.** 초안: `docs/plan/draft/20261116-0853-언어-비교-시험판.md`.
