## 지금 무엇이 불편한가

리모델링 진단(`docs/remodel/20261116-진단.md`)에서 사용자가 「바꾼다」로 판정한 칸(2026-11-16). 언어는 파이썬 유지 — 이 일은 파이썬 안에서 한다. 순서: 시험과 검사 → 이미지 파일 저장 → 폴더 구조(앞 일이 뒤 일의 안전망).

`pasteflow/main.py`가 3,551줄이고 커밋 333개 중 158개(47%)가 이 파일을 건드린다. 1,000줄 넘는 파일이 5개(`main.py`·`ui/image_annotator.py`·`ui/panel.py`·`ui/settings_dialog.py`·`paste_interceptor.py`). 순차 붙여넣기 규칙이 `paste_queue.py`·`paste_interceptor.py`·`main.py`에 나뉘어 있다.

## 원하는 동작

- 두 백지 설계의 처방을 파이썬 안에서: 순수 로직(Windows를 모름 — 순차 붙여넣기 규칙·히스토리 정책)과 Windows 연결부(키 훅·클립보드·창)를 나눈다.
- `main.py`를 기능별 모듈로 나눈다(동작은 바꾸지 않는다).
- 앞 일의 파일 길이 검사가 지키게 한다.

## 어떻게 되면 끝인가

`main.py`가 크게 줄고(목표 숫자는 문서에서), 순차 붙여넣기 규칙이 운영체제 없이 시험되는 한 곳에 있다. 시험이 모두 통과하고 앱이 평소처럼 동작한다.

## 하지 않는 것

- 화면 파일(주석 편집기·패널·설정창) 쪼개기 — 디자인 규칙 검사 때 다시 본다.
- 기능 바꾸기.
