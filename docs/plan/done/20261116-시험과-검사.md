## 2. 원하는 동작

### 커밋할 때

1. Claude(또는 사람)가 Paste_flow에서 `git commit`을 치면 전역 훅이 `.claude/commit-gate.json`을 읽는다.
2. 바뀐 파일이 규칙의 `paths`(`*.py` · `tests/**` · `pasteflow/**` · `requirements*.txt` · `tools/**`)에 걸리면 `python tools/check_file_length.py && python -m pytest -q -p no:cacheprovider tests`를 저장소 최상위에서 돌린다. 문서만 바뀌었으면 시험 없이 통과한다.
3. 둘 다 성공하면 커밋된다. 하나라도 실패하면 커밋이 막히고 실패 출력이 보인다.

### 파일 길이 검사 `tools/check_file_length.py`

- 저장소의 `.py` 파일(추적 중 + 스테이징 + 추적 안 되는 새 파일, `.gitignore`가 빼는 것은 제외)을 모은다. `git ls-files --cached --others --exclude-standard`로 목록을 얻는다.
- HEAD 커밋에 없는 파일(`git cat-file -e HEAD:<경로>`가 실패)이 「새 파일」이다. 새 파일이 300줄을 넘으면 그 파일과 줄 수를 찍고 종료 코드 1.
- 기존 파일 중 300줄 넘는 것은 「참고 — 큰 파일 N개」로 줄 수 큰 순서대로 찍기만 한다(종료 코드에 영향 없음).
- HEAD가 없는 저장소(첫 커밋 전)면 모든 파일을 새 파일로 친다.
- 표준 라이브러리만 쓴다. 이 스크립트 자체도 300줄 아래로.

### 순차 붙여넣기 조합 시험 `tests/test_paste_queue_stateful.py`

- `hypothesis`의 상태 기계 시험(`RuleBasedStateMachine`)으로, 진짜 `PasteQueue`와 이 시험 파일 안의 짧은 기준 모형(목록 + 포인터 + 마지막 복사 시각만 가진 순수 파이썬)을 같은 사건 순서로 같이 움직이고 매 단계 둘이 같은지 본다.
- 사건: 복사(`add_item`, 항목마다 고유 id) · 순차 붙여넣기(`get_next`, 돌려준 항목이 모형과 같은지) · 평범한 Ctrl+V(`mark_plain_paste`) · 되돌리기(`undo_last`) · 줄 지정(`set_queue`, 포인터는 0부터 항목 수 사이) · 비우기(`clear`) · 항목 삭제(`remove_item`, 줄에 있는 id와 없는 id 둘 다) · 시간 흐르기(가짜 시계를 0초·5초·10초·11초 앞으로).
- 시간은 시험 안에서 `pasteflow.paste_queue` 모듈의 `time` 이름만 가짜 시계 객체(`monotonic()`만 가진 것)로 바꿔 진짜로 기다리지 않는다 — 파이썬 전체의 `time.monotonic`을 바꾸면 `hypothesis` 자신의 시간 재기까지 흔들린다. `hypothesis` 설정은 `deadline=None`(느린 PC에서 시간 초과 헛실패 방지).
- 매 단계 확인: 진짜와 모형의 (포인터, 항목 id 목록)이 같다 · 0 ≤ 포인터 ≤ 항목 수 · `is_exhausted()`가 「포인터 ≥ 항목 수」와 같다.
- 기본 실행 수는 `hypothesis` 기본값(100가지 순서). 커밋 검사 시간이 2초를 넘으면 `max_examples`를 줄인다.
- 시험이 진짜 `PasteQueue`의 버그를 찾으면 **고치지 않는다** — `hypothesis`가 줄여 준 반례(사건 순서)를 문서 「검사 기록」과 보고에 적고, 조합 시험 함수를 `pytest.mark.xfail(strict=False, reason=<반례 한 줄>)`로 표시해 커밋 검사를 막지 않게 한다(고치기는 따로).

### 커밋 검사 설정 `.claude/commit-gate.json`

```json
{
  "rules": [
    {"name": "길이 검사와 시험", "paths": ["*.py", "tests/**", "pasteflow/**", "requirements*.txt", "tools/**"], "run": "python tools/check_file_length.py && python -m pytest -q -p no:cacheprovider tests", "cwd": "."}
  ]
}
```

실패했을 때 보이는 것: 길이 검사가 실패하면 「새 파일 <경로> <줄 수>줄 — 300줄 넘음」, 시험이 실패하면 pytest 출력 마지막 줄들이 커밋을 막은 이유로 보인다.
