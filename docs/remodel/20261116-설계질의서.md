# 설계 질의서 — 개인용 Windows 클립보드·캡처 작업 허브를 처음부터 만든다면

생성: 2026-11-16
용도: 리모델링 진단의 「백지 설계」 입력. 이 글만 보고 답한다 — 기존 구현은 없다고 생각한다.

## 1. 무엇을 위한 도구인가

- 만드는 사람이자 유일한 사용자: 방송 엔지니어 한 명. 개발 전공이 아니고, AI 코딩 도구(터미널에서 AI에게 시켜 코드를 쓰게 하는 방식)로 만든다. 코드를 직접 읽고 고치는 일은 드물다.
- 목표: 복사·붙여넣기·화면 캡처·녹화·음성 입력을 단축키로 다루는 「내 Windows 작업 허브」를 매일 막힘없이 쓰는 것. 기능을 더 넓히기보다, 지금 기능을 버그 없이 매일 쓰고 불편은 그때그때 고치는 단계다.
- 시작 계기: 「복사한 순서대로 붙여넣기」를 하는 도구를 두 번 만들다 실패했다. 실패 원인은 붙여넣기 키를 가로채서 막는 방식의 타이밍 문제였다.
- 환경: Windows 10(1903 이상)·11 전용. 혼자 쓰고, 다른 사람에게 배포할 계획은 없다. PC 3~4대에서 같은 것을 쓴다.

## 2. 기능 (모두 지금 쓰는 기능)

**순차 붙여넣기 (핵심)**
- A, B, C 순서로 복사한 뒤 「순차 붙여넣기 단축키」(Ctrl+Shift+V)를 누를 때마다 A, B, C가 차례로 붙는다. 켜고 끄는 모드는 없다(항상 동작).
- 꼭 지킬 동작: 붙여넣기 키 입력을 막지 않는다. 키가 눌리는 순간(떼기 전) 시스템 클립보드 내용을 「다음 항목」으로 바꿔 두고, 키 입력은 그대로 대상 앱에 보내 운영체제가 붙여넣게 한다. 도구가 스스로 클립보드에 쓴 것을 새 복사로 착각하지 않는다.
- 줄(큐)을 비우는 때: 붙여넣기를 시작한 뒤 새로 복사함 · 마지막 복사 뒤 일정 시간(기본 10초)이 지나 새로 복사함 · 평범한 Ctrl+V를 누름. 줄이 다 소진되면 개입하지 않는다(마지막 항목이 계속 붙는다).
- 텍스트·이미지·서식 있는 글(HTML·RTF)·노션 같은 앱 전용 형식까지 원래 형식 그대로 되살려 붙인다.
- 이미지 항목을 「임시 그림 파일의 경로 글자」로 바꿔 붙이는 모드(하나씩 / 끝까지 자동). AI 코딩 도구에 그림을 넘길 때 쓴다.

**클립보드 패널**
- 복사가 일어나면 작은 패널이 화면 구석에 뜬다. 이때 지금 쓰던 창의 입력 초점을 빼앗지 않는다. 단축키(Ctrl+Space)로 직접 열 때만 초점을 가져간다.
- 히스토리(기본 50개, 10~500 설정) + 고정 항목(재시작 뒤에도 남음, 끌어서 순서 바꾸기). 항목마다 번호·종류 아이콘·두 줄 미리보기 또는 썸네일·시간.
- 클릭하면 그 항목을 대상 앱에 바로 붙임(순차 줄에는 영향 없음). 여러 개를 골라 「순차 붙여넣기 줄」로 지정. 우클릭 메뉴(붙이기·고정·복사·삭제·글자 인식·AI에게 질문 등). 패널에서 다른 앱으로 끌어다 놓기.
- 순차 붙여넣기 진행 상태 표시(예: 1/3), 진행 중 줄 목록 작은 표시창.
- 빠른 메모창: 단축키로 바로 열고 쓰는 동안 자동 저장, 항상 위·글자 크기 조절. 메모는 패널에 쌓이고 잠근 것만 남기고 한 번에 비우기(바로 되돌리기 가능).

**캡처·녹화·편집**
- 화면 영역 캡처: 창과 창 안의 부품(버튼·편집 영역 등) 경계에 자석처럼 달라붙는 선택, 자유 끌기, 여러 모니터를 가로지르는 선택, 마우스 커서 포함 여부 토글.
- 같은 영역 선택으로 움직이는 그림(GIF) 녹화와 영상(MP4) 녹화. 영상은 길이 제한 없이 파일로 바로 흘려 쓴다.
- 이미지 미리보기 창 여러 개 동시, 휠 확대·끌어 이동. 그 자리에서 주석 편집: 도형·선·화살표·펜·글자·번호표.

**AI 연동 (회사 AI 게이트웨이 — 여러 회사의 AI 모델을 하나의 웹 API로 쓰게 해 주는 사내 서비스)**
- 화면 글자 인식: 영역을 고르면 글자를 뽑아 클립보드로(영역을 고를 때 특정 키를 누르면 번역). 이미지 우클릭으로도.
- 음성 입력: 단축키로 녹음을 시작하면 커서 옆에 음량에 반응하는 작은 표시가 뜨고, 끝내면 받아쓴 글을 붙인다. 마이크 장치 선택.
- 이미지에 대해 묻기: 이미지를 첨부한 질문을 브라우저의 AI 검색으로 보낸다.
- 설정창에서 모델 고르기와 「연결 시험」 버튼. API 키는 Windows 사용자 계정으로 암호화해 이 PC에만 저장.

**그 밖**
- 시스템 트레이 상주, 트레이 클릭으로 패널. Windows 시작 때 자동 실행 설정.
- 모든 단축키를 설정창에서 바꿈(충돌 감지). 패널 위치·크기 기억.
- 우하단에 쌓이는 알림(복사됨·시작·글자 인식 결과 등).
- 어두운 화면 테마, 대비 높게.

## 3. 비기능 요구

- 복사 감지 지연 100ms 미만, 순차 붙여넣기 때 클립보드 교체 50ms 미만.
- 상시 실행 메모리 80MB 미만, 쉴 때 CPU 0.5% 미만, 시작 뒤 트레이에 뜨기까지 3초 미만.
- 비정상 종료에도 히스토리를 잃지 않는다.
- 설치는 간단해야 한다(파일 하나를 받아 실행하는 정도가 이상적). 업데이트를 PC 3~4대에 쉽게 퍼뜨려야 한다.

## 4. 만드는 사람의 사정 (설계에 반영해 달라)

- AI가 코드를 쓰고 사람은 결과를 써 보며 확인한다. 그래서 「AI가 실수해도 기계가 잡아 주는 구조」(자동 시험·검사, 작은 단위로 나뉜 파일)가 사람의 꼼꼼함보다 중요하다.
- 화면을 자주 바꾼다. 화면 부품을 다시 쓰기 쉬워야 한다.
- 운영체제 깊은 곳(전역 키 감지, 클립보드 형식, 다른 창의 부품 경계 알아내기, 화면 녹화, 마이크)을 많이 건드린다.
- 사용자는 범위를 크게 잡는 것을 꺼리지 않는다 — 언어를 통째로 바꾸거나 화면 도구를 처음부터 다시 고르는 것도 후보다. 지금 무엇으로 만들었는지는 일부러 알려 주지 않는다.

## 5. 답해 줄 것

아래 여섯 칸마다 **고를 것과 이유**를 적어 달라. 비슷한 후보가 있으면 2등과 「무엇이 바뀌면 2등이 낫나」도. 한 칸도 빼지 말 것.

1. **언어** — 앱을 무엇으로 짤까
2. **화면 도구** — 패널·설정창·오버레이·주석 편집기를 무엇으로 그릴까
3. **폴더 구조** — 파일과 폴더를 어떤 단위로 나눌까(예: 기능별·층별), 큰 파일을 어떻게 막을까
4. **데이터 저장** — 히스토리·고정·설정·이미지를 어디에 어떤 꼴로 둘까
5. **시험과 검사** — 무엇을 자동으로 시험·검사할까(운영체제를 건드리는 부분은 어떻게)
6. **배포** — 어떻게 빌드하고 PC 3~4대에 설치·업데이트할까

마지막으로, 이 도구에서 **가장 위험한 기술 지점 세 곳**과 각각을 어떻게 다룰지 적어 달라.
